# Local AI beta 0.2.0

## Benchmark follow-up: 0.2.1

Report `5613e225-da6d-4fdc-a4ec-18797ef92865` from an Infinix X6886 with 8,060,694,528 bytes reported RAM completed all six clean-English speech runs with zero WER on one 22-word clip. Tiny took 2.56–2.858 s; Base took 5.241–5.759 s after a 74.189 s first run. All six silence cases returned nonempty output. All nine Qwen cases failed JSON parsing. Qwen observed app PSS peaked at 1,785,381,888 bytes. This is an approximately 8 GB phone, so 4 GB support remains unvalidated. The V1 report does not identify the returned silence text or why Qwen JSON failed.

Version 0.2.1 uses llama.rn's pure-content Jinja mode with thinking disabled and validates the answer `content` field instead of raw `text`. A fallback to raw text is allowed only when the content field is absent in an older result shape. Empty content, interrupted/truncated/token-limited completions, malformed JSON and ungrounded passages are rejected. There is no JSON substring salvage or weakened source checking. This addresses an integration mismatch; device inference must be rerun to establish whether it resolves the observed failures.

Audio preparation is unchanged. A bounded PCM scan skips only digital near-silence (sample magnitudes at most one PCM16 unit), before loading Whisper. It is not general voice activity detection; quiet speech/noise/music remain decoder inputs. Known Whisper blank/silence markers are removed from transcript text and segments. V2 benchmarks test silence twice: `silence-5s` bypasses the amplitude gate to exercise decoding/marker handling; `silence-gated-5s` exercises the complete pipeline. A successful gated test alone is not a claim about Whisper's silence robustness.

V2 report diagnostics separate model verification, preparation and model loading; Qwen cases record input/output token counts, content/raw/reasoning character counts, content shape, truncation/stop flags and per-chunk completion time. Transcript text, model output and reasoning are not included. Memory settings and model weights are unchanged so the measured memory concern remains open. Existing V1 reports remain readable; rerun the prerecorded suite on 0.2.1 without making new recordings.

## Native build follow-up

The first AI preview build (`4a832422-8143-4415-9c17-6e04eee53176`, version code 3) was canceled after exactly 2,700,003 ms (45 minutes) while running R8. No compiler error or APK was reported; this is consistent with the EAS plan timeout. The initial configuration built all llama.rn JNI CPU variants. The Expo config plugin now limits compilation to the generic fallback, ARMv8.2 and ARMv8.2 dot-product variants; the native loader falls back when other variants are absent. High-end i8mm/DSP variants are not included in this build selection. Phone performance must be measured with this selection.

Internal preview builds disable R8 minification/resource shrinking to reduce build time and enable EAS compiler caching. Production retains the Expo release optimization defaults. The preview APK may be larger; prompt secrecy never depended on obfuscation. Native projects remain generated through Expo plugins. A replacement build is required before device validation.

## Implementation

SDK 58 Expo application, Continuous Native Generation, Android arm64 preview APK. Native inference uses whisper.rn 0.7.4 and llama.rn 0.13.0-rc.9. The local Expo module prepares audio with Android MediaExtractor/MediaCodec, streams a simple low-pass/resampling stage into mono 16 kHz WAV chunks, and samples process memory/thermal state. Conversion quality needs device validation, especially noisy or high-frequency audio. Root Android project files remain generated by Expo.

Models are pinned to immutable Hugging Face revisions with byte lengths and SHA-256 digests in `catalog.ts`. Model hashes are streamed with bounded JS buffers; verified receipts are checked and files are rehashed on first use per launch. Downloads alone use the network. Models can be deleted independently of notes. Native inference artifacts use the dependency's checksum-verified installer, with script approval limited to that pinned dependency.

Whisper Tiny/Base multilingual Q8 transcribes 30-second chunks. CPU-only Qwen3 0.6B Q8 extracts up to eight exact passages per bounded chunk, with a 2048-token context and at most 768 output tokens. Both use two threads; the speech context is released before the note context loads. No whole-recording PCM allocation is required. The official Q8 model is larger than community Q4 variants but has an official immutable source.

Five deterministic layouts organize source passages: meeting minutes, recording summary, casual note, study notes, and action checklist. These are extractive drafts. They may omit useful details, misclassify passages or inherit transcription errors. They do not infer missing dates, speakers, owners or decisions. Corrections are encouraged before generation.

## Data safety and security

SQLite V2 migration preserves the V1 library and audio metadata. Transcripts carry revisions. Saving against an outdated revision fails; drafts against older transcripts cannot be accepted. Acceptance requires user action and stores the previous description for restoration. Draft creation never overwrites the description. Original audio is not modified. Derived FTS includes transcript text and follows corrections/deletion.

Recorded speech is treated as untrusted input. A fixed prompt and constrained JSON schema are followed by strict key/type/count/length validation and exact source-substring checks for every passage. The model has no tools, file writes, network calls or code execution. Output is plain text. Source instructions can still influence passage selection or classification: this is not a proof against all prompt injection. Local prompts are inspectable and cannot be kept secret; no credentials or secrets are placed in them.

Local workload limits replace cloud quota enforcement: one task/download globally, bounded recording/file/transcript/context/output sizes, a low-available-memory guard for Qwen, cancellation, and foreground-only work. There is no backend or billable API endpoint to rate-limit. This is not tamper-proof enforcement against a modified app.

Temporary decoded audio is cleaned after completion/failure/cancellation. App termination can leave cache files until Android reclaims them. SQLite and app-private files are not separately encrypted by this app. Normal exports and the explicit report link remain user-controlled sharing paths.

## Automated benchmark and acceptance

Bundled public-domain JFK speech (attribution under assets/benchmark), generated five-second silence, and fictional English/Filipino/Taglish text fixtures run without microphone input. Optional existing audio import stays local and can be scored against a supplied reference transcript. One or three repetitions load a fresh model context per case. Hash verification/loading/conversion are included where performed; filesystem cache warmth can differ across repetitions.

Reports persist locally and export only app/device/model metadata, elapsed time, 500 ms sampled PSS, process-lifetime RSS high-water, available memory, thermal status, WER/edit counts, literal expected-fragment coverage, schema/source validation and format rendering results. They contain no raw audio or full transcripts. Native error messages may contain local file paths; review exports before sharing. Completion is not an accuracy pass. No threshold or speed claim is established yet.

Validation completed on the development machine: SQL and grounding/scoring unit tests, TypeScript, ESLint and Android JavaScript export. These do not execute native model inference. Native EAS compilation and physical-phone checks are separate gates.

Before claiming 4 GB support, run on a physical arm64 4 GB device: download models, enable airplane mode, run three repetitions at comparable temperatures; verify M4A decoding, cancellation/retry, background interruption, sequential model release, transcript correction, stale-draft rejection, acceptance/restoration, model deletion/redownload, low-storage behavior and existing-library upgrades. Record Android/device/app/model versions and results. Measure cold/warm latency and memory; check no process kills. Compare transcript and drafts against actual recordings, including natural Filipino/Taglish and noisy meetings. Bundled English speech/text smoke tests alone are insufficient. Battery energy, broad speech quality, speaker diarization and long-recording usability remain unvalidated.
